我根据这个视频的英文自动字幕整理了。视频核心是：**用最短时间掌握 Obsidian 最重要的 80% 功能，并避免新手常见误区**。链接：[YouTube 视频](https://www.youtube.com/watch?v=z4AbijUCoKU)

**1. 为什么选择 Obsidian**

Obsidian 适合三类需求：

- 想低摩擦记录自己的想法
- 想用链接和反向链接连接知识
- 想提升思考、学习、写作，同时保留本地优先、离线可用、可迁移的数据格式

作者强调：Obsidian 本质上不是一个封闭 App，而是一个读取本地文件夹的工具。

**2. Obsidian 的本质**

Vault 就是电脑上的一个文件夹。

里面的笔记是独立的 Markdown 文本文件，可以被很多软件打开，比如：

- Obsidian
- VS Code
- 普通文本编辑器
- 其他 Markdown 编辑器

所以即使 Obsidian 以后不用了，你的笔记也还在。这就是它的“你拥有自己的数据”的优势。

**3. 同步方式**

Obsidian 本身是本地优先的。如果要多设备同步，可以用：

- Dropbox 等云盘
- Obsidian Sync 官方同步服务

视频特别提到 Obsidian Sync 的优点：

- 端到端加密
- 版本历史
- 官方服务，相对省心

**4. 基础界面**

左侧主要是文件列表，可以：

- 新建笔记
- 新建文件夹
- 按文件名、修改时间等排序
- 自动定位当前打开的文件
- 展开 / 折叠文件夹
- 搜索整个 vault
- 使用书签保存重要笔记

中间是笔记编辑区。

标签页可以拖动、拆分成多个面板，适合多笔记并排处理。

**5. 最重要的能力：边写边链接**

Obsidian 的核心不是文件夹，而是链接。

用双中括号创建内部链接：

```markdown
[[某个笔记]]
```

即使这个笔记还不存在，它也会作为“占位链接”出现。之后可以点击它创建新笔记。

这很适合边写边发现新概念，比如：

```markdown
这让我想到 [[技术美术]] 和 [[Shader Variant 管理]]
```

**6. Graph View 图谱**

每个笔记会变成图谱里的一个节点。

- 已创建笔记是一个节点
- 未创建但被链接的笔记也会显示
- 链接越多，图谱越能显示知识之间的关系

作者认为图谱可以帮助发现意外联系，但新手不要只沉迷图谱视觉效果。

**7. 反向链接 Backlinks**

每篇笔记可以看到有哪些其他笔记链接到了它。

这就是 Obsidian 的强项之一：  
你不只知道“这篇笔记链接了谁”，还知道“谁提到了这篇笔记”。

适合复盘一个概念在不同场景中的出现位置。

**8. 必开设置：自动更新内部链接**

作者强烈建议打开：

```text
Settings → Files and Links → Automatically update internal links
```

作用是：当你重命名一篇笔记时，Obsidian 会自动更新其他笔记里的链接。

否则你改名后，旧链接可能断掉。

**9. 附件文件夹设置**

建议把图片、PDF、附件统一放进附件文件夹。

可以在设置里修改默认附件路径，避免图片、文档散落在笔记列表里，导致侧边栏混乱。

**10. 主题设置**

视频里推荐安装主题：

```text
AnuPpuccin
```

作者把它作为某种 “soft paper” 风格的基础主题使用。

这个不是必需知识点，只是美观和阅读体验优化。

**11. 新手误区一：不要把旧笔记全部导入**

作者明确反对一上来把旧笔记 App 里的几千条内容全部倒进 Obsidian。

原因是：

- 会立刻变乱
- 很难找到东西
- 旧系统的问题会被搬进新系统
- 你还没建立 Obsidian 的使用习惯

建议：先从新笔记开始，逐步迁移真正有价值的内容。

#### **12. 新手误区二：不要一开始狂装插件**

视频点名不要第一天就沉迷：

- Advanced Tables
- Kanban
- Dataview dashboards
- 各种复杂插件

作者建议先掌握基础链接、笔记、组织方式。插件应该服务于已经出现的需求，而不是反过来制造复杂度。

#### **13. 新手误区三：不要过度建文件夹**

这点和你前面问的“文件夹焦虑”非常相关。

作者认为：知识类笔记很难放进固定父子文件夹，因为一个笔记经常可以属于 5 到 10 个不同类别。

所以不要按随机主题疯狂建文件夹。

建议：

- 先用大分类
- 结构要“长出来”，不要提前设计太细
- 用链接、快速切换、图谱和 MOC 来找笔记

#### **14. 新手误区四：不要拖延学习快捷键**

作者认为快捷键会显著降低记录阻力。Obsidian 越快用，越容易坚持。

常用快捷键包括：

```text
Cmd/Ctrl + B：加粗
Cmd/Ctrl + I：斜体
Cmd/Ctrl + F：当前页搜索
Cmd/Ctrl + T：新建标签页
Cmd/Ctrl + W：关闭标签页
Cmd/Ctrl + P：命令面板
Cmd/Ctrl + O：快速切换笔记
```

Mac 是 Command / Option，Windows 对应 Control / Alt。

**15. Markdown 常用语法**

视频列了一组基础格式：

```markdown
# 一级标题
## 二级标题

**加粗**
*斜体*
~~删除线~~
==高亮==

> 引用

- 项目符号
1. 编号列表
- [ ] 待办事项

`行内代码`

```代码块```
```

外部链接：

```markdown
[显示文字](https://example.com)
```

内部链接：

```markdown
[[笔记名]]
```

嵌入其他笔记：

```markdown
![[笔记名]]
```

嵌入图片或外部资源：

```markdown
![](图片链接)
```

**16. 快速切换器**

用：

```text
Cmd/Ctrl + O
```

可以快速搜索并打开笔记。

作者认为这比一层层翻文件夹更高效。

**17. 推荐的基础文件夹结构**

作者推荐一个大框架，叫 ACE：

```text
Atlas
Calendar
Efforts
```

含义是：

```text
Atlas：长期知识、思想、概念
Calendar：日期型内容，比如日记、每日笔记
Efforts：有时间边界的项目、任务、当前投入
```

这其实和 PARA 有点像，但更偏作者自己的系统。

对你来说可以翻译成：

```text
Atlas = 知识库
Calendar = 每日记录
Efforts = 项目 / 正在做的事
```

**18. 书签 Bookmarks**

重要笔记可以加入书签。

方式包括：

- 点笔记右上角菜单
- 用命令面板搜索 bookmark 命令

适合固定入口，比如：

- 当前项目首页
- 学习路线
- MOC
- 常用索引页

**19. 标签 Tags**

可以用 `#标签` 给笔记打标记。

但作者并不鼓励过度依赖标签。他更推荐 MOC。

标签适合表达类型或状态，比如：

```markdown
#todo
#idea
#draft
#reference
```

不太适合承担复杂知识结构。

**20. MOC：Maps of Content**

作者更推荐用 MOC 组织主题。

MOC 本质是一篇“目录型笔记”，里面手动链接相关笔记。

例如：

```markdown
# 技术美术 MOC

- [[Shader Variant 管理]]
- [[URP Renderer Feature]]
- [[贴图压缩]]
- [[美术资源规范]]
```

MOC 的优势是：

- 比文件夹灵活
- 可以一个笔记出现在多个 MOC 中
- 能形成图谱里的强连接中心
- 更适合主题、领域、知识网络

**21. Daily Notes 每日笔记**

如果你经常快速记录想法，可以用每日笔记。

每日笔记适合放：

- 临时想法
- 当天任务
- 学习记录
- 突然冒出来的概念
- 稍后再整理的链接

然后从每日笔记链接到正式知识笔记。

**22. Obsidian 支持多种内容格式**

虽然核心是 Markdown，但也可以放：

- 图片
- PDF
- 音频
- 其他文档
- YouTube 嵌入
- 推文嵌入
- 表格
- 模板
- Canvas 白板

图片可以直接拖入笔记。

#### **23. Core Plugins 核心插件**

视频提到几个内置核心插件：

- Audio Recorder：录音备忘
- Templates：模板复用
- Canvas：白板式组织
- Bases：用属性组织和筛选笔记

这些是 Obsidian 自带生态的一部分，不一定需要社区插件。

#### **24. Properties 属性**

可以给笔记添加属性，比如：

- 创建日期
- checkbox
- 链接
- 文本
- 数字
- 类型
- 状态

快捷键：

```text
Cmd/Ctrl + ;
```

属性适合放结构化信息，不会污染正文。

例如：

```yaml
status: draft
type: concept
created: 2026-05-12
area: 技术美术
```

**25. Bases 功能**

视频提到可以把 Properties 和 Bases 结合，用来做更高级的组织、排序、更新。

可以理解成：  
用数据库视图的方式管理 Markdown 笔记。

比如按类型、状态、项目筛选笔记。

**26. Canvas 白板**

Canvas 是 Obsidian 的可视化白板，可以拖入：

- 笔记
- 图片
- 卡片
- 其他素材

适合头脑风暴、项目规划、知识结构梳理。

**27. AI 与 Obsidian**

作者强调：Obsidian 本身没有内置 AI。

这反而是优点，因为你可以自己决定：

- 用不用 AI
- 用哪个 AI
- AI 能访问多少笔记
- 隐私和便利之间怎么权衡

作者提到自己用 Claude 来：

- 向笔记提问
- 和笔记对话
- 做深度研究
- 自动填充属性

但他也强调：

- 使用 AI 前先备份
- 区分自己的原创想法和 AI 生成内容
- 不要让 AI 污染自己的核心知识库

**28. 视频整体方法论**

这个视频不是在教你“搭一个复杂系统”，而是在强调：

```text
先简单记录
边写边链接
少用文件夹
少装插件
逐步长出结构
用 MOC 组织主题
用属性和 Bases 做进阶管理
```

结合你自己的情况，我觉得最该吸收的是这几条：

```text
1. 不要用文件夹承载复杂知识分类
2. 一个技术点可以同时链接到多个主题
3. 先用大文件夹，细结构以后再长出来
4. MOC 比主题文件夹更适合 Obsidian
5. 先建立低摩擦记录习惯，再考虑插件和自动化
```

这其实正好回答你最开始的困惑：  
**“开发文档”和“技术美术”不应该争一个父文件夹。它应该放在一个稳定的大桶里，然后同时链接到两个 MOC。**
